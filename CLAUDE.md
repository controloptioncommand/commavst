# Правила проекта Comma

Comma — вайбкод VST3/AU/CLAP-эффект для macOS, C++ / JUCE 8: rack для экспериментов с высотой тона — микротональность (EDO, just intonation, строи Scala) и MPE-глайды. Ориентир по звуку — микротональная электроника вроде Aloboi. Брат Mist, Eido, Sumi, chrōma и Granula: те же темы, шрифты и страница About.
Репозиторий публичный: https://github.com/controloptioncommand/commavst

Перед любой работой с интерфейсом прочитай **[docs/DESIGN.md](docs/DESIGN.md)** — это обязательная дизайн-система.

## Версии и патчноуты
- Текущая версия — в файле `VERSION`. На странице About она же в `Source/UI/About.h` (`AboutInfo::version`, `AboutInfo::date`).
- Схема: v0.1 — каркас, v1 — все модули. Дальше: минорный апдейт — число после точки +1 (v1.1, v1.2 …), мажорный — первая цифра. Какой апдейт какой, решает пользователь.
- **У каждой версии обязателен патчноут** `docs/releases/<версия>.md` — без него CI не соберёт релиз.
- Новая версия: поменять `VERSION` и `AboutInfo` → добавить патчноут → коммит в `main`. CI сам соберёт, проверит (pluginval, auval, тест) и опубликует релиз с архивом `Comma-macOS.zip`.
- Пока `VERSION` не меняется, новые сборки перезаписывают текущий релиз. Ветки `claude/**` только собираются (архив — в Artifacts сборки), релиз не публикуют.
- Ссылка на последнюю сборку: https://github.com/controloptioncommand/commavst/releases/latest/download/Comma-macOS.zip
- После публикации дать пользователю эту ссылку и команду установки:
  ```bash
  cd ~/Downloads && rm -rf Comma-macOS Comma-macOS.zip && gh release download -R controloptioncommand/commavst -p Comma-macOS.zip && unzip -q Comma-macOS.zip -d Comma-macOS && bash Comma-macOS/install-mac.sh
  ```

## Сборка и проверка
```bash
cmake -B build -DCOMMA_BUILD_TESTS=ON && cmake --build build --target CommaTest
./build/CommaTest_artefacts/Release/CommaTest ./render   # на Linux — через xvfb-run -a
```
Нужен C++20 (tuning-library). На Linux для JUCE нужны пакеты `libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxext-dev libxcomposite-dev libfreetype6-dev libfontconfig1-dev libasound2-dev libgl1-mesa-dev`.
Тест: строй (12-EDO, N-EDO с корнем, отношения, `.scl` + `.kbm` с пропущенными клавишами, битый `.scl`, Болен — Пирс, MTS-ESP без мастера, загрузка файлов и состояние), единицы интервала, питч-шифтеры по БПФ (±10 ¢ — линия задержки и PSOLA; большие сдвиги — свободное окно в пределах ± половины частоты окна, окно в периодах — точно), YIN, Hermite, математика rack'а на тестовых модулях, нотный слой (MCM, бенд участников и мастера, RPN 0, pressure, slide, lift, Glide во времени / скорости / герцах, Snap, характер, посадка, 16 голосов), модули (Doubler L/R и шаг 24-EDO, эхо Staircase по ступеням, Shifter ±100 Гц и зеркальная частота ниже −30 dB, синхронизация, Harmonizer 3/2 в обоих режимах, Autotune к строю и к ноте, Resonator на ноте и бенде и тишина после, матрица pressure → ручка, Varispeed +100 ¢ / тормоз / разгон / рампа, Spectral snap / копия при Amount 0 / stretch под тритаву), задержки (последовательно — сумма, параллельно — максимум, всё выключено — копия со сдвигом), процессор, состояние (и проект v0.1), undo, все 20 шаблонов, 40 бросков кубика, 44.1 / 48 / 96 кГц и блоки 1–4096, скорость, скриншоты в обеих темах, About. Перед коммитом тест должен печатать `ALL OK`. После изменений интерфейса — посмотреть скриншоты.

Высоту шифтеров на линии задержки при больших сдвигах мерить YIN, а не пиком БПФ: перекрёстное затухание головок даёт боковые полосы.

## Что нельзя ломать
- **Аудиопоток работает в реальном времени**: в `processBlock` и `Module::process` нет выделений памяти, блокировок, ввода-вывода. Буферы — в `prepare`. Параметры сглаживаются.
- Строй собирается в потоке сообщений (`refreshTuning`; tuning-library бросает исключения и выделяет память) и передаётся в аудиопоток готовым снимком через `TuningHolder` (кольцо из 32 указателей держит память, аудиопоток читает сырой указатель).
- Высоты — в «абсолютных центах» (центы над MIDI-нотой 0 в 12-EDO); интервал — сложение. Шаги строя: модуль знает высоту — настоящие ступени (`shiftSteps`), не знает — средний шаг.
- Состав rack'а передаётся в аудиопоток одним 64-битным атомарным числом (`RackLayout::pack`); смена состава — затухание 5 мс, переключение, нарастание 5 мс.
- **Каждый модуль встречается в rack'е не больше одного раза**, все параметры заведены заранее одной таблицей (`Params.cpp`, `P::…`), их ID не меняются — иначе ломается автоматизация в проектах. ID из v0.1 (`*_on`, `*_mix`, `output`) — версия 1, остальные — 2.
- Слот: `z = dry + mix · (wet − dry)`, dry задержан на задержку модуля. Группа: `(Σ wₖ·zₖ + d·x) / (Σ wₖ + d)`, `d = max(0, 1 − Σ wₖ)`. Слоты группы выравниваются по самому медленному; хосту сообщается сумма задержек групп. Bypass задержку не меняет.
- Задержку модуля считает поток сообщений (`computeLatency` → `setLatency`), модуль по ней понимает свой режим. PSOLA — `3 · ceil(sr / 60) + 4`, Spectral — 2048 / 1024.
- Модуль отдаёт «мокрый» сигнал (как при Mix 100 %); смешивание, bypass и выравнивание делает `Rack`.
- Нотный слой считает высоты раз в 32 семпла; Resonator читает их по `blockOffset` (Rack режет блок на куски).
- Мод-матрица: эффекты без голосов получают сведённое MPE (последняя нота / самая высокая / среднее), Resonator — на каждый голос (`ModMatrix::voiceValue`).
- Выход: громкость, NaN → 0 со сбросом rack'а, мягкий предел — ниже 0.98 сигнал не трогается, выше упирается в 0 dBFS.
- Дробные задержки — не хуже кубической интерполяции (Hermite).
- Кубик не трогает Output, состав rack'а, bypass, строй, нотный слой, матрицу, режимы задержки, Sync, тормоз; Mix ≥ 40 %, обратная связь ≤ 75 %. Порядок слотов — только если включено в настройках (по умолчанию выключено).
- Пресет не трогает Output; фабричный задаёт строй, но не трогает файлы Scala; свой пресет несёт rack и строй (отношения, `.scl`, `.kbm`).
- Изменение диапазонов параметров ломает старые проекты и пресеты — предупреждать.

## Этапы
Все этапы плана сделаны (v0.1 — каркас, v1 — строй, MTS-ESP, круг и анализатор, Doubler и Staircase, нотный слой MPE и Resonator, Shifter, Harmonizer и Autotune, Varispeed, Spectral). Дальше — по запросам пользователя.

## Структура
- `Source/Tuning/` — `Tuning` (снимок строя, EDO, отношения, Scala через tuning-library, единицы интервала, `TuningHolder`), `MTS` (клиент и мастер MTS-ESP)
- `Source/Notes/NoteLayer.*` — MPE, голоса, Glide, Snap, характер, посадка
- `Source/DSP/DSP.*` — задержка с Hermite, `DelayShifter`, биквад, Гильберт, YIN, PSOLA
- `Source/Rack/` — `Module` (интерфейс, `ProcessContext`, `ModMatrix`), `Rack`, `Modules.cpp` (Doubler, Staircase, Shifter, Varispeed), `ModulesVoice.cpp` (Harmonizer, Autotune, Resonator), `Spectral.cpp`
- `Source/PluginProcessor`, `Params`, `Presets`, `Randomizer` — параметры, строй и rack в состоянии (`Rack` → `Slot`, `Tuning`), мод-матрица, undo, шаблоны, кубик
- `Source/UI/` — `LookAndFeel`, `Widgets`, `About` (общие с братьями), `MainView` (круг строя, Pitch / Notes / Matrix), `RackView` (слоты), `ModulePanel` (ручки модулей)
- `Tests/CommaTest.cpp` — офлайн-тест; `scripts/` — установка и проверка приватности; `docs/` — руководство (`Comma-manual.pdf`, исходник в `docs/manual/`), дизайн, картинки README, патчноуты
- При изменении ручек и поведения — обновлять руководство (`docs/manual/Comma-manual.html` → `bash docs/manual/build.sh`) и README (пасхалки там не упоминать).
